なぜ npm が狙われる？

依存する package へと広がっていく
機微情報 + package の publish 権限 が奪える → 次の攻撃へ

攻撃する側にとってコスパがいい

では、なぜ npm がこんなに狙われるのか。攻撃する側の目線で考えてみます。まず、パッケージを1つ乗っ取るだけで、推移的依存をたどって、何千、何万というプロジェクトに一気に届きます。次に、届く先は開発者の PC や CI です。そこには、クラウドの鍵や npm のトークンが置いてあることが多い。それを盗めば、今度はそのトークンで別のパッケージを乗っ取れます。keyv の件では、この連鎖で、最初は十数個だったパッケージが、4時間足らずで444パッケージ、2,212バージョンまで広がりました。少ない手間で、大きな見返りが得られる。使う側にとって便利な仕組みは、攻撃する側にとっても割がいいんです。
